# 은하 — "처음의 우주" 설계 (Phase C1)

> 요구사항 원문은 [`docs/COSMOS_PROMPT.md`](COSMOS_PROMPT.md)에 있습니다. 이 문서는 그 요구를 지금 코드 위에 어떻게 올릴지 정한 설계이며, 이 문서를 쓰는 동안 소스 코드는 바꾸지 않았습니다.
> 결정 다섯 가지는 2026-10-06에 모두 권장안으로 확정되었습니다(1절).

## 0. 요약

- 테마 id는 `cosmos`, 탭 이름은 "은하", 장면 이름은 "처음의 우주"입니다.
- 이 테마는 **우주의 나이 A = W − W₀**만 읽습니다. W₀는 이 테마를 처음 고른 순간의 W입니다.
- 시뮬레이션은 **닫힌 형태의 일정 + 사건 단위 장부**입니다.
  - 무엇이 언제 생기는지(연대기, 항성계 단위의 시작과 끝, 이정표)는 시드와 A만으로 정해집니다.
  - 자원(가스, 별먼지, 얼음, 물)은 사건 순서대로 장부에 기록되고, 그 장부가 항성계의 풍성함(행성 수)을 정합니다.
  - 숲·우주처럼 작업자가 길을 찾는 시뮬레이션이 아니라서 계산이 가볍고, 세션을 어떻게 나눠도 결과가 같습니다.
- 장면은 **화면 공간의 고정 구도**입니다. 깊이 9겹에 시차(parallax)를 주고, 장면이 직접 가진 작은 카메라(이동·줌 저역통과)를 씁니다. 땅이 없는 장면이라 숲·우주의 원근 카드 디오라마는 쓰지 않습니다(5.1절).
- 기존 숲·우주의 시뮬레이션, 장면, 저장 데이터, 테스트는 바꾸지 않습니다. 고치는 곳은 테마 목록이 두 개라고 가정한 분기들(4절)뿐입니다.

## 2. 시간과 저장

### 2.1 원점 W₀

```ts
World.cosmos?: { origin: number; resets: number }   // 데이터 버전 3 안의 선택 필드
```

- **기록 시점**: 엔진의 모든 커밋 뒤에 정규화 함수 하나를 적용합니다. `settings.theme === 'cosmos'`인데 `world.cosmos`가 없으면 `origin = worldTime(s, now)`로 한 번 기록합니다.
  - 테마를 고르는 순간, 다른 탭에서 고른 상태를 받은 순간, 은하 테마인 채로 "새 풍경"을 만든 순간(새 세계의 W=0)이 모두 같은 규칙으로 처리됩니다.
- **새 우주 시작**: `origin = worldTime(s, now)`, `resets + 1`. 숲·우주의 상태와 `bankedMs`는 건드리지 않습니다.
- **데이터 버전은 올리지 않습니다.** 선택 필드라서 옛 저장은 그대로 읽히고, `validWorld`가 이 필드를 검사해 보존합니다(음수가 아닌 수, origin ≤ bankedMs + 열린 세션).
- 알려진 한계(지금과 같은 종류): 배포 전에 열려 있던 옛 버전 탭이 저장하면 이 필드와 테마 선택이 빠질 수 있습니다. 다음에 은하를 고르면 그 시점이 새 원점이 됩니다.

### 2.2 A와 러너

- `A = max(0, W − origin)`
- `SimRunner('cosmos')`는 `base = { W: origin, legacy: null }`로 만듭니다. 그래서 체크포인트의 `baseW`가 원점과 같고, 새 우주를 시작하면 옛 체크포인트가 자동으로 버려집니다.
- 은하는 `COSMOS_SIM_VERSION`을 따로 둡니다. 숲·우주의 `SIM_VERSION`을 올리지 않으므로 그 체크포인트도 그대로 유효합니다.
- `app/sim.ts`의 러너 키에 원점을 넣습니다(`${worldId}:${origin}:cosmos`).

## 3. 시뮬레이션 (`src/sim/cosmos.ts`)

### 3.1 왜 닫힌 형태인가

숲·우주는 작업자가 길을 찾고 자원을 기다리는 시뮬레이션이라 결과를 사건 순서대로만 알 수 있습니다. 은하의 "작업자"는 중력의 흐름이고 기다리는 일이 없습니다. 그래서 **언제** 생기는지는 시드와 A의 순수 함수로 두고, **얼마나 풍성한지**만 장부로 정합니다. 그 결과는 다음과 같습니다.
- 진행 단계, 이정표, 세션 사건의 자격 조건을 시뮬레이션 상태 없이도 계산할 수 있습니다(UI·사건 일정에서 가볍게 씀).
- 분할 독립이 구조적으로 보장됩니다. 장부는 사건을 정수 ms 순서로 처리합니다.

### 3.2 항성계 단위 일정

- 단위 0은 집의 항성계로, 연대기가 끝나는 1,460초에 완성됩니다.
- 단위 k ≥ 1의 길이는 `d_k = 9분 + 7분 × (u₁+u₂)/2`(시드 해시, 평균 12.5분)이고, 앞 단위가 끝나는 순간 시작합니다. 끝 시각 배열은 시드별로 누적해 메모합니다(2,000시간에 약 9,600개).
- 단위 안의 진행(비율):

  | 진행 | 사건 |
  |---|---|
  | 0.00–0.25 | 가스 흐름. 흐름 꾸러미 8개가 0.03 + 0.03·i에 도착(가스 −1씩) |
  | 0.10–0.25 | 원시별 |
  | 0.25–0.35 | 점화 |
  | 0.35–0.55 | 원반 |
  | 0.55–0.85 | 행성 n개가 고르게 하나씩 생김(별먼지·얼음 장부 사건) |
  | 0.85–0.95 | 소행성대·혜성 구름 |
  | 0.95–1.00 | 다음 매듭으로 흐름이 뻗음 |

- 별의 종류(해시): 붉은 왜성 0.36, 노란 별 0.36, 푸른 거성 0.18, 쌍성 0.10. 쌍성은 단위 8부터이고, 그 전에는 노란 별로 바꿉니다.
- 위치: 구역 `z = ⌊k/16⌋`, 성단 `c = ⌊(k mod 16)/4⌋`, 성단 안 자리 `j = k mod 4`. 단위 0~3이 첫 성단입니다.

### 3.3 자원 장부

| 자원 | 들어옴 | 나감 |
|---|---|---|
| 가스 | 거미줄 유입 `80 + ⌊A/60초⌋`(닫힌 형태), 초신성마다 +6 | 1세대 별 점화 6, 집의 별 12, 단위마다 흐름 8 |
| 별먼지 | 초신성마다 +18 | 암석 행성 하나에 1 |
| 얼음 | 집의 원반 바깥 30(1,440초), 가스 행성 하나에 +2 | 생명의 행성으로 가는 혜성 하나에 1 |
| 물 | 혜성 하나에 +1 | — |

- **풍성함**: 지금까지 생긴 별먼지 총량 Z로 `richness = min(6, 1 + ⌊Z/36⌋)`를 정합니다. 단위의 행성 수는 `n = min(cap(종류), richness)`입니다(cap: 붉은 왜성 3, 노란 별 6, 쌍성 4, 푸른 거성 0).
  - 암석 행성은 `⌈n/2⌉`개이되 남은 별먼지를 넘지 않고, 가스 행성은 `⌊n/2⌋`개입니다. 위성과 고리는 해시로 붙습니다(행성 4개 이상일 때 위성, 가스 행성의 30%에 고리).
  - 예상 흐름: 25분에 1개 → 35분에 2개 → 1.6시간에 3개 → 2.7시간에 4개 → 5시간에 5개 → 7시간에 6개. C4에서 측정해 표로 남깁니다.
- 푸른 거성은 점화 뒤 40~90분(해시)에 초신성이 됩니다. 별은 사라지고, 잔해(성운 조각과 펄서)가 남습니다. 지금까지 생긴 항성계 수는 줄지 않습니다.
- **불변식**: 자원마다 들어온 양 = 나간 양 + 남은 양이고, 음수는 없습니다. 공급이 수요보다 커서(가스 60/시간 대 최대 53/시간, 별먼지 약 16/시간 대 약 8/시간) 일정이 자원을 기다리는 일은 없습니다. 테스트로 확인합니다.

### 5.1 장면을 화면 공간으로 두는 이유

- 숲·우주의 디오라마는 땅 위의 원근 카드입니다. 은하에는 땅이 없고, 요구도 "고정 시점, 화면 폭 8% 이내 이동"입니다.
- 그래서 모든 요소를 정규화 화면 좌표(0..1, wide/tall 표)로 두고, 층마다 시차 계수(근경 1.0, 중경 0.6, 원경 0.25)를 곱한 카메라 변환만 적용합니다.
- 호스트의 카메라 리그에는 늘 같은 framing을 넘겨 리그를 멈춰 둡니다. 숲·우주의 카메라 문법(2단 저역통과, 점프 때 보간 없이 맞춤)은 장면 카메라가 그대로 따릅니다.

## 6. 사건

### 6.1 이정표 (A에 고정, 한 번)
연대기 이정표(빅뱅, 첫 빛, 첫 별, 첫 초신성, 첫 성운, 집의 별, 첫 행성계)와 두 번째 성운, 달의 탄생, 첫 성단, 바다의 시작, 가스 행성의 고리, 은하 원반, 생명, 은하 핵 각성, 첫 불빛입니다.
- 연출 창(headline)을 가지며, 세션 사건과 드문 사건은 이 창을 피합니다.
- 실행 중에 지날 때만 연출합니다. 점프 뒤에는 연출이 끝난 상태로 그립니다(모든 연출이 A의 함수이므로, 점프 뒤에 "지금 A의 모습"을 그리면 됨).
- "자세히"의 우주 연표는 지나간 이정표의 A와, 그 A가 들어 있던 세션 구간의 날짜로 만듭니다.

### 6.2 세션 사건 (`cosmosSights(seed, origin, segs)`, 화면 전용)

| 규칙 | 값 |
|---|---|
| 시작 가능 | A ≥ 1,460초(연대기 뒤) |
| 첫 사건 | 세션 시작 + max(30초, min(T × 0.25~0.45, 1분 30초~3분 30초)) |
| 간격 | 4분~6분 30초, 앞 사건과 최소 3분 30초 |
| 끝 여유 | 세션 끝 − min(60초, T × 0.15)까지 끝남 |
| 길이 | 40~120초(남은 자리에 맞춰 최소 40초) |
| 없음 | 2분 미만 세션, DEV 습격 표지 구간 |
| 겹침 | 이정표·드문 사건 창이면 그 뒤로 미룸 |
| 종류 | 단계에 맞는 후보에서 가중치로, 같은 종류 연속 금지 |

스톱워치는 열린 세션에서 12시간 앞까지 계획합니다(우주의 `pacedSights`와 같음). 세션을 일찍 끝내면 아직 오지 않은 사건만 빠집니다.

### 6.3 드문 사건 (A의 30분 블록, `timeline.ts`의 `eventOfBlock` 재사용)
대혜성(5+), 킬로노바(6+), 떠돌이 행성(4+), 별 탄생 폭발(7+)이 블록마다 많아야 하나입니다. 행성 정렬(8+)은 궤도에서 정해지는 4.8시간 주기의 정해진 창이고, 드문 사건 블록이 이 창을 피합니다.

### 6.4 우주 날씨 (A의 36분 블록)
상태는 맑은 별빛, 성간 먼지 띠, 항성풍, 성운이 밝은 밤 넷입니다. 강도 `{dust, wind, glow}`를 연속값으로 두고 2~4분 smoothstep으로 전이하며, 첫 블록은 맑음입니다. Director에 넘기는 weather 심각도는 0입니다(우주 날씨가 앰비언트를 막지 않음).

### 6.5 헤드라인 우선순위
이정표 > 드문 사건 > 세션 사건 순입니다. `env.event`로 Director에 넘겨 fx·ambient를 조절합니다.

## 7. 배경 별과 세션 별자리

- 별 i는 `A = 240초 + 30초·i`에 켜집니다. 위치·색·밝기는 `hash(seed, i)`로 정하고, 타이머 여백(wide x 0.30–0.70, y 0.22–0.66 / tall y 0.08–0.52)과 근경 궤도 띠는 피해서 다시 뽑습니다.
- 최근 400개만 낱개 스프라이트로 그립니다. 그 이전 별은 은하수 띠의 밝기(최대치 있음)로 합칩니다.
- 별자리는 세션 구간 [w0, w1]을 A로 바꿔 그 사이에 켜진 별 가운데 밝은 4~9개를 고르고, 프림 알고리즘으로 최소 신장 트리를 만듭니다.
  - 이름은 꾸밈말 48 × 사물 48 목록에서 `hash(seed, ⌊w0⌋)`로 정합니다.
  - 2분 미만이거나 별이 3개 미만이면 만들지 않습니다.
  - 선을 남기는 것은 최근 4개입니다. "자세히"에는 최근 600 세션(pace 보관 한도)까지 나옵니다.
- 실시간 완료(`celebrate`)일 때만 4~6초 그리기 연출을 합니다. 나머지는 바로 투명도 0.12로 그립니다.

## 8. 장면 연출 메모 (C3~C7에서 채움)

- **빅뱅 번짐**: 불규칙한 가장자리를 칠한 큰 번짐 텍스처를 씨앗점에서 ease-out으로 키웁니다(12초). 안개 텍스처 3장은 TilingSprite의 UV 흐름과 tint 램프(금 → 주황 → 장미 → 자두)로 움직입니다.
  - 밝기 상한(화면 평균 상대 휘도 0.35)은 안개 알파와 색으로 맞추고, C3에서 프레임 휘도를 측정합니다.
- **투명해짐**: 가장자리 안개(가운데가 빈 텍스처)가 먼저 걷히고, 가운데 안개가 나중에 걷힙니다.
- **수채 성운**: 번짐 띠가 있는 반투명 덩어리를 여러 번 겹쳐 칠한 텍스처 2~3겹입니다. 겹마다 다른 노이즈 주기로 위치·알파를 흔듭니다.
- **원반과 은하의 회전**: 납작하게 누른 컨테이너(scale.y) 안의 스프라이트를 회전시킵니다. 이렇게 하면 비스듬한 타원 회전이 됩니다.
- **생명의 행성**: 표면 지도(TilingSprite, 가로 흐름이 곧 자전)를 원 마스크로 자르고, 그 위에 명암(별 쪽)·대기 테·구름(다른 속도)·불빛(밤면만) 층을 얹습니다. 행성 방문 때 확대하므로 지도는 512px로 칠합니다.
- **매 프레임 다시 그리는 Graphics**는 별자리 그리기(4~6초)와 흐름 띠뿐이며, `gfx.ts` 규칙으로 따로 묶습니다.
- 입자(불티, 거미줄 가스, 흐름 구슬, 유성)는 Director 예산 안에서 씁니다.

## 10. 위험

- **범위가 큽니다.** 장면 대부분이 새 그림입니다. 그림 품질(수채 번짐, 생명의 행성)은 Phase마다 스크린숏으로 판단하고, 부족한 점은 남은 점에 그대로 적습니다.
- **밝기**: 빅뱅과 초신성은 본질적으로 밝은 장면입니다. 상한을 지키면 화려함이 줄어들 수 있으므로, 밝기 대신 색과 번짐의 크기로 표현합니다.
- **성능**: 생명의 행성 마스크와 안개 TilingSprite 몇 장이 새 비용입니다. 0 / 4 / 2,000시간에서 측정합니다.
- **실기기**: 숲·우주와 마찬가지로 휴대폰·저사양 기기에서는 직접 측정할 수 없습니다.

| 첫 별 | 0.36ms | 60 | 60 | 788 |

- headless 화면은 60fps에 묶여 있습니다. 숲·우주 기록과 같은 144Hz 측정이 아니므로, fps로 직접 비교할 수 없습니다.
- 텍스처는 54장이고, 화면 비율별 거미줄 텍스처가 처음 쓸 때 3장 더해집니다.

**남은 점(관찰 그대로)**
- 실제 속도 5분 녹화의 2프레임(110초, 164초)에 정지 포스터가 찍혔습니다(그 순간 fps 0). 원인은 확인하지 못했습니다.
  - 같은 조건으로 재현을 시도했지만, 스크린숏 없이 180초, 2초마다 스크린숏 72장을 찍으며 150초 동안 WebGL 컨텍스트 손실, 캔버스 상태 변화, 250ms 넘는 프레임 공백이 모두 0건이었습니다.
  - 녹화 때 다른 세션의 개발 서버와 브라우저가 같은 GPU를 쓰고 있었습니다. 실제 사용 중에도 일어나는지는 모릅니다.
- 실제 속도로 끝까지 본 것은 5분, 6분, 2분짜리 실행뿐입니다. 25분 세션 전체와 여러 시간 실행은 실제 속도로 보지 않았습니다(저속 촬영과 시간 이동으로 확인).
- 생명·바다 이정표 방문은 실제 속도로 녹화하지 않았습니다. 같은 카메라 방문 코드이고, 녹화로 본 것은 달과 첫 불빛입니다.
- 행성 정렬은 테스트(각도 일치)로만 확인했고, 화면에서는 보지 않았습니다.
- 소리는 코드만 있습니다. 귀로 들어 확인하지 않았습니다.
- 별자리 모양은 화면 비율(가로/세로)마다 다릅니다. 같은 세션에 같은 이름이 붙지만, 별의 위치가 비율별로 다르기 때문입니다.
- 쌍성의 춤, 별 탄생, 달 그림자는 크기를 키운 뒤에도 데스크톱에서 작게 보입니다. 상태 문구로 무엇이 일어나는지 알립니다.
