# 전선 — "아스테르 변경" 설계 (Phase F1)

> 요구사항 원문은 [`docs/FRONT_PROMPT.md`](FRONT_PROMPT.md)에 있습니다. 이 문서는 그 요구를 지금 코드 위에 어떻게 올릴지 정한 설계입니다. 이 문서를 쓰는 동안 소스 코드는 바꾸지 않았습니다.
> 결정 11가지는 2026-10-06에 모두 확정되었습니다(1절). 줄 번호는 커밋 `38fefd0`(은하 "쌓이는 하늘과 문명의 시대") 기준입니다.

## 0. 요약

- 테마 id는 `front`, 탭 이름은 "전선", 장면 이름은 "아스테르 변경"입니다. 우주(`space`) 탭과 장면을 대체합니다.
- 이 테마는 **전쟁 시간 A = W − W₀**만 읽습니다. W₀는 종족을 고른 순간의 W입니다.
- 시뮬레이션은 은하와 같은 **닫힌 형태**입니다.
  - 무엇이 언제 생기는지는 (시드, 종족, A)만으로 정해집니다. 건물, 일꾼, 병력, 티어, 점령전, 행성 장악, 궤도전, 강하, 함선이 모두 그렇습니다.
  - 자원 장부도 같은 일정에서 닫힌 형태로 계산하는 표시용 값입니다. 일정이 자원을 읽지 않으므로, 세션을 어떻게 나눠도 결과가 같다는 것이 구조적으로 보장됩니다.
- 세션 맞춤 전투(전투 등급, 무대, 무대 전환)와 작전 기록은 세션 구간 기록에서 나오는 **화면 전용** 결과입니다. 성장에는 영향을 주지 않습니다.
- 장면은 은하처럼 **장면 전용 카메라**를 씁니다. 호스트 리그는 멈춰 둡니다.
  - 무대는 셋입니다: 지상(쿼터뷰), 궤도, 성계.
  - 지상 무대는 "지도 좌표 → 화면" 투영에 약한 원근 배율을 더한 2.5D 스프라이트 장면입니다. 숲·우주의 원근 카드 디오라마는 쓰지 않습니다.
- 우주는 탭, 장면, 포스터, 소리, DEV 블록을 지웁니다.
  - 시뮬레이션(`sim/space.ts`, `raid.ts`, `spacePlan.ts`), 이관(`sim/v1`), 저장 데이터(`world.base.space`, `moa:v3:sim:space`)는 남깁니다.
  - 남는 코드가 컴파일되도록, 테마 목록보다 넓은 시뮬레이션 테마 타입을 하나 둡니다(4.1절).

## 2. 시간과 저장

### 2.1 원점 W₀와 종족

```ts
type RaceId = 0 | 1 | 2;     // 0 연합, 1 군체, 2 공명단
World.front?: {
  cur?: { origin: number; race: RaceId }; // 지금 전쟁. 없으면 "종족 선택 전"
  resets: number;
  dates?: [number, number][];             // [세션 시작 bankedMs, 벽시계] — 작전 기록의 날짜
  past?: { origin: number; race: RaceId }[]; // 지난 전쟁(최근 20)
}
```

- **은하와 다른 점: 화면에 보이는 것만으로는 기록하지 않습니다.**
  - 은하는 테마가 화면에 보이면 `withCosmosOrigin`으로 바로 원점을 기록합니다.
  - 전선은 종족을 고를 때만 기록합니다. 그래서 `theme === 'front'`이면서 `world.front?.cur`가 없는 상태가 저장될 수 있습니다. 이 상태가 "종족 선택 전"입니다.
- 기록 시점
  1. 종족 카드를 고른 순간: `chooseRace(s, now, race)`
  2. 고르지 않고 시작을 누른 순간: `start()`가 같은 커밋 안에서 시드 종족 `defaultRace(seed)`로 기록합니다.
  3. 세션이 도는 중에 전선 탭으로 바꾼 순간: 카드를 고를 자리(프리셋 자리)가 없으므로 시드 종족으로 바로 기록합니다. 커밋 정규화 `withFrontOrigin`이 처리합니다.
- **새 전쟁 시작**: `newWar(s, now)`는 `cur`를 `past`에 넣고 지워서 종족 선택 전으로 돌립니다. `resets`는 하나 늘리고, `dates`와 `past`는 그대로 둡니다. 숲·은하·`bankedMs`·`base`는 건드리지 않습니다.
- **새 풍경**: `createNewWorld`는 새 세계를 만들므로 `world.front`가 없습니다. 은하와 같습니다.
- 데이터 버전은 올리지 않습니다. 선택 필드이고, `validWorld`(`core/persist.ts:176`)에 `v.front` 검사를 더합니다.
  - `cur`가 있으면 origin은 음수가 아니고 ≤ bankedMs + 400일, race는 0·1·2(어긋나면 `cur`만 버림)
  - resets는 정수, dates와 past는 걸러서 보존
- 알려진 한계(은하와 같은 종류): 배포 전에 열려 있던 옛 탭이 저장하면 `world.front`가 빠지고, 테마가 숲으로 바뀔 수 있습니다(`persist.ts:264`의 허용 목록). 그 경우 다음에 고를 때 새 원점이 생깁니다.

### 2.2 설정의 테마

- `persist.ts:264`의 허용 목록에 `'front'`를 더하고, `'space'`는 `'front'`로 읽습니다.
- `migrate.test.ts:217`은 이제 `'front'`를 기대해야 합니다.
- 기본 테마는 그대로 `'forest'`입니다.

### 2.3 A와 러너

- `A = max(0, W − origin)`. 종족 선택 전에는 A = 0이고, 시뮬레이션은 시드 종족의 A=0 그림(착륙 직후)을 보여줍니다.
- `SimRunner('front')`는 은하처럼 `base = { W: origin, legacy: null }`로 만듭니다. 종족 선택 전에는 러너를 만들지 않고 `frontAt(seed, race, 0)`을 바로 씁니다. 원점이 매 프레임 바뀌는 키를 피하기 위해서입니다.
- 러너 키: `${worldId}:${base.W}:front@${origin}:${race}`(`app/sim.ts:43-48`, 옛 `:front@` 키는 지움).
- `FRONT_SIM_VERSION`을 따로 둡니다. 숲·은하의 버전은 올리지 않습니다.

## 3. 시뮬레이션 (`src/sim/front.ts`)

### 3.1 왜 닫힌 형태인가

- 숲·우주처럼 작업자가 길을 찾는 사건 시뮬레이션으로 만들면, 세 종족 × 일곱 행성 × 수십 유닛의 상태를 체크포인트로 들고 다녀야 합니다.
- 화면에 필요한 것은 "그 시각에 무엇이 있었나"뿐입니다. 그래서 모든 것을 (시드, 종족, A)의 함수로 둡니다.
- 일정은 시드마다 한 번 만들어 메모해 둡니다(은하처럼 Map 16개까지).
- 러너 상태는 `{ v, seed, race, origin, t, done }`만 들고 다닙니다. `advance`는 `t = A`만 합니다. 체크포인트 형식과 규칙은 기존 그대로 쓰지만, 사실상 캐시가 필요 없을 만큼 가볍습니다.

### 3.2 일정표 개요

```ts
interface FrontPlan {                 // planOf(seed, race)
  open: OpenBeats;                    // 2.4절 상수(종족별 물건 이름만 다름)
  planets: PlanetPlan[];              // 성계 1의 7개 + 다음 성계는 필요할 때 늘림
  tiers: TierTimes;                   // 3.4절
  ships: ShipPlan;                    // 3.6절
  rivals: [RaceId, RaceId];           // 왼쪽·오른쪽 경쟁 세력(시드)
}
interface PlanetPlan {
  idx: number; biome: BiomeId;
  orbitAt: number;                    // 궤도 국면 시작(첫 행성은 없음, -1)
  landAt: number;                     // 강하(첫 행성은 0)
  captures: Capture[];                // 3.5절, 시간순
  bases: BaseEvent[];                 // 내 기지 시작·완성
  builds: BuildEvent[];               // 건물 시작·완성(기지·슬롯·종류)
  decisiveAt: number;                 // 결전 시작
  conqueredAt: number;                // 장악(결전 끝)
}
```

### 3.3 행성 일정

| 값 | 첫 행성 | 다음 행성 p |
|---|---|---|
| 강하 | 0 | `orbitAt + 10분` |
| 궤도 국면 | — | `conqueredAt(p−1) + 18~24분` 시작, 10분 |
| 장악 | 85~95분(시드) | `landAt + 72~110분` |

- 그 결과 행성 사이 간격은 1시간 40분~2시간 24분(평균 약 2시간)이고, 장악은 1:30 → 3:30 → 5:30 → … 즈음입니다. 성계(7행성)는 약 13~15시간입니다.
- **전선 행성**: `landAt ≤ A`인 마지막 행성입니다. 기본 무대는 전선 행성의 지상입니다.
  - 다만 `orbitAt ≤ A < landAt` 동안은 다음 행성의 궤도 무대가 기본입니다. 이 구간은 사건이 아니라 상태라서, 새로고침해도 같은 화면입니다.
- **개발 행성**: `conqueredAt ≤ A`인 행성이고, 단계는 장악 뒤 경과 시간으로 정합니다.

  | 경과 | 0 | 2시간 | 5시간 | 10시간 |
  |---|---|---|---|---|
  | 단계 | 개척 | 도시 | 궤도 정거장 | 행성 요새 |

- 성계 k의 행성 생태
  - 성계 1: 표 순서(카르나 … 아스테르의 심장)
  - 성계 2부터: 앞 여섯의 해시 순열과 마지막 "심장"

### 3.4 티어와 병력

| 티어 | 열리는 A | 비고 |
|---|---|---|
| T1 | 230초 | 첫 병력 |
| T2 | 870초 | 2티어 기술 720~870 |
| T2 특수 | 30분 | |
| T3 | 45분 | 3티어 기술 |
| T4a 호위함 | 첫 장악(약 1:30) | 궤도 조선소 60~85분 |
| T4b 주력함 | 3시간 | |
| T4c 기함 | 5시간 | 개발 행성 둘 이상일 때 |

- **병력 수 N(A)**: 구간 선형 곡선입니다. 그 뒤로는 시간당 +5가 이어지다가 120(약 17시간)에서 멈춥니다(`ARMY_MAX`). 그 뒤의 성장은 개발 행성·함선·티어로 보입니다. 화면 표시는 60에서 멈춥니다.

  | A | 4분 | 10분 | 25분 | 50분 | 1:30 | 3:00 | 5:00 |
  |---|---|---|---|---|---|---|---|
  | N | 1 | 6 | 15 | 30 | 45 | 55 | 60 |

- **i번째 유닛의 생산 시각**은 N(A)의 역함수로 정합니다. 생산 건물은 시드로 고르고, 종류는 그 시각의 조합 비율(프롬프트 4.6절)에서 해시로 뽑습니다.
- 쓰러진 유닛은 후송·귀환하므로 수는 줄지 않습니다. 전투는 화면 전용입니다.
- **일꾼**: 4 → 6(100초) → 8(5분) → 12(12분) → 기지마다 +6, 기지당 최대 12입니다. 화면 표시는 30에서 멈춥니다.
- **업그레이드 휘장**: 1(12:30), 2(40분), 3(1:10)
- **경쟁 세력**의 티어는 같은 표에서 `lag = 12~18분`(시드) 늦게 열립니다. 병력 수는 내 N의 0.6~0.8배입니다.

### 3.5 점령전과 영토

- 행성마다 지대 12곳과 본진 셋이 있습니다. 지대 배치는 6절의 지도 표를 따르고, 행성 시드로 흔듭니다.
- **점령전 시각**
  - 첫 행성은 오프닝 안의 1020~1170초에 첫 점령전이 있습니다.
  - 그 뒤로는 `OPEN.end`부터 간격 10~14분으로 이어집니다. 간격에 전황 배수를 곱합니다(공세 ×0.7, 폭풍 ×1.6).
  - 재착륙 행성은 600초부터 시작합니다.
- **결과 규칙**(시드로 뽑되 아래 제약을 지킴)

  | 종류 | 비율 | 규칙 |
  |---|---|---|
  | 내가 지대를 얻음 | 약 70% | 중립을 먼저, 그다음 적 확장. 적 확장을 처음 얻는 것이 "전선 돌파"(1시간 근처에 오도록 순서를 고정) |
  | 경쟁 세력이 중립을 얻음 | 약 20% | |
  | 내 외곽 지대를 잠시 잃음 | 약 10% | 세 번째 기지 이후의 지대만. 잃으면 다음 공세 국면 안의 점령전에서 반드시 되찾음 |

- **점령률** = (내 지대 + 내 본진·앞마당 가중) / 전체입니다. 행성마다 장악 직전에 75% 이상이 되도록, 마지막 몇 점령전은 내가 얻는 것으로 고정합니다.
- **결전**: 장악 시각 150초 전에 시작합니다. 장악 시각은 3.3절의 일정이 정하고, 그 전에 점령률이 75%를 넘도록 점령전 순서를 맞춥니다. 결전 동안 화면의 전황은 공세 강도로 덮어씁니다.
- 공세 국면마다 점령전이 적어도 하나 있게 만듭니다. 잠시 잃은 외곽 지대를 "다음 공세 국면 안에" 되찾는 규칙이 늘 성립하게 하기 위해서입니다.
- **영토 반지름**: 기지·지대가 내 것이 된 뒤 경과 시간 s에 대해 `r = r0 + (r1 − r0)·(1 − e^(−s/20분))`입니다. 화면 마스크는 이것만 읽습니다.

### 3.6 함선

- 호위함: 첫 장악 시각부터 8분마다 하나, 48척(약 7시간 50분)에서 멈춥니다. 화면 표시는 8척까지입니다.
- 주력함: 3시간부터 25분마다 하나, 16척(약 9시간 15분)에서 멈춥니다. 화면 표시는 4척까지입니다.
- 기함: A 4시간 45분 이후, 개발 행성이 둘 이상인 첫 공세 국면의 시작(대개 약 4시간 48분)에 출격합니다(이정표).
- 경쟁 세력 함선은 같은 규칙을 lag만큼 늦게 따릅니다.

### 3.7 자원 장부 (표시용, 닫힌 형태)

- **캔 양** `mined(A)`
  - 일꾼 j가 합류한 시각 a_j, 왕복 시간 trip_j(20~30초, 해시), 위상 φ_j가 있습니다. 하역 횟수는 `⌊(A − a_j − φ_j)/trip_j⌋⁺`이고, 한 번에 광석 5를 내립니다.
  - 열샘은 열샘 시설 완성 뒤의 일꾼 셋에 같은 식을 씁니다(4씩).
  - 시결정은 시결정 지대를 가진 동안 분당 1입니다.
- **쓴 양** `spent(A)`: A까지 시작한 건물·유닛·함선 비용의 합입니다. 비용은 표로 둡니다. 예: 보급 100, 생산 건물 150, 1티어 50, 2티어 125/50(광석/열샘), 3티어 300/200, 호위함 400/300/2(시결정), 주력함 800/600/6, 기함 2000/1500/20.
- **재고** = 캔 양 − 쓴 양입니다.
  - 일정표를 만들 때 모든 지출 시각에서 재고 ≥ 0인지 확인합니다. 부족하면 그 항목을 다음 하역 뒤로 미루는 "지출 시각 조정"을 한 번 합니다. 일정은 시드마다 한 번만 만들어지므로 분할 독립성은 그대로입니다.
  - 테스트로 3분마다 60시간 동안 재고 ≥ 0을 확인합니다.
- 보급 한도는 시작 건물 10에 보급 건물 하나마다 8을 더합니다. 일정표는 보급 건물을 병력의 보급 합보다 늘 앞서 짓습니다.

|---|---|---|

## 5. 세계 계층 (`src/world/front.ts`, 화면 전용)

### 5.1 전황의 계절

- `tideAt(A)`
  - A < `OPEN.end`이면 `{ phase: 'open' }`입니다.
  - 그 뒤 `q = (A − OPEN.end) / 12분`, 국면 = ⌊q⌋ mod 4(정비·증강·공세·폭풍)입니다.
  - 연속 강도 `{ bustle, march, storm }`는 경계 ±75초를 smoothstep으로 잇습니다.
- 재착륙 오프닝 동안에도 국면은 계속 돕니다. 화면은 재착륙 박자를 먼저 보여줍니다.

### 5.2 세션 전투

```ts
frontBattles(seed, race, origin, segs): Battle[]   // WeakMap<segs> → "seed:race:origin" 메모
interface Battle extends WorldEvent {
  kind: BattleKind; grade: 1..7;
  stage: 'ground' | 'orbit'; planet: number;       // planet ≠ 전선 행성이면 무대 전환
  enemy: 0 | 1;                                    // 왼쪽·오른쪽 경쟁 세력
  big: boolean;                                    // 세 번째마다
}
```

- **간격**: 은하의 `SIGHT_PACE`와 같은 값입니다. 처음 1분 30초~3분 30초, 그 뒤 4~6분 30초, 최소 3분 30초, 2분 미만 세션 없음, 세션 끝 전에 끝남.
- **피하는 구간**: `OPEN.end` 전, 재착륙 오프닝 600초, 이정표와 점령전 ±90초(뒤로 밀기), 궤도 국면(상태이므로 그 무대 안의 궤도 전투로만 고름).
- **등급**: 열린 등급 가운데 최근 40%, 바로 아래 30%, 나머지 30%를 해시로 고릅니다. 같은 등급 세 번 연속은 없습니다. 폭풍 국면의 지상 전투는 폭풍 사건(작음)으로 바꿉니다.
- **무대 전환**
  - 개발 행성이 둘 이상이면 각 전투가 1/3 확률로 다른 행성(개발 행성 가운데 하나)에서 일어납니다.
  - 직전 전투가 다른 행성이었으면 0입니다. 최근 15분에 두 번이면 0입니다.
  - 개발 단계가 높을수록 궤도 비율이 큽니다: 개척 20%, 도시 40%, 정거장 60%, 요새 70%.
  - "자동 카메라 끔"은 장면에서만 판단합니다. 사건 목록은 같고, 화면만 전환하지 않습니다.
- **결정성**: 같은 세션 기록이면 같은 목록입니다. 세션을 일찍 끝내면 아직 오지 않은 전투만 빠집니다(우주 `pace.ts`와 같은 성질).

### 5.3 드문 사건

`FRONT_DEFS`는 A의 30분 블록에 놓습니다. 은하의 `COSMOS_DEFS`처럼 `eventOfBlock`을 재사용하고, `theme: 'front'`로 둡니다. 자격 조건은 프롬프트 11절 ④의 열리는 때를 A로 검사합니다.

### 5.4 headline

`frontHeadlineAt(seed, race, origin, W, segs)`는 아래 순서로 가장 먼저 해당하는 것을 돌려줍니다. 시간은 W로 돌려 씁니다(은하의 `cosmosHeadlineAt`과 같은 틀).

1. 이정표(`ms:`)
2. 점령전(`cap:`)
3. 드문 사건
4. DEV 사건
5. 세션 전투

### 5.5 작전 기록

- `operationName(seed, segIndex)`: 꾸밈말 48 × 사물 48의 목록에서 고릅니다. 세션 번호와 시드의 해시를 씁니다.
- `operationRecords(seed, race, origin, segs, W, dates)`: 세션마다 다음을 계산합니다.
  - 그 구간 [w0, w1]의 A 차이에서 확장, 병력, 점령률 변화, 막아 낸 전투 수, 궤도전 승리 수
  - 깃발을 꽂을 지대: 구간 안에서 주인이 바뀐 지대 가운데 마지막 것. 없으면 영토가 가장 많이 자란 기지
- 2분 미만 세션은 빼고, 화면 깃발은 최근 5개만 남깁니다.

### 6.2 지상 투영

- **지도 좌표**: x ∈ [0, 1]은 왼쪽 → 오른쪽, y ∈ [0, 1]은 먼 쪽 → 가까운 쪽, z는 고지대 높이(0, 1, 2단)입니다.
- **화면**
  - `X = x·w`
  - `Y = top + y·(h − top) − z·cliff`. `top`은 하늘 띠 아래(데스크톱 0.12h, 모바일 0.08h)이고, `cliff`는 0.035h입니다.
- **약한 원근**: 크기 배율 `s(y) = 0.80 + 0.30·y`(먼 쪽이 작음)입니다. 그리기 순서는 (y, z) 정렬입니다.
- 줌 1.0에서는 지도 좌표가 화면 비율과 같습니다. 그래서 프롬프트 6절의 배치표가 곧 지도 좌표표입니다.
- **줌 단계**(1.6 / 1.3 / 1.1 / 1.0): 카메라 피벗은 본진 고지대 중심입니다. 줌 1.6에서도 타이머 여백 뒤에 호수가 오게, 본진을 화면 아래쪽(y 0.80)에 둡니다.

### 6.4 궤도와 성계 무대

- **궤도 무대**
  - 행성 지평선 텍스처(행성별 1장, 1024×256)가 y 0.70–1.0의 호를 이룹니다.
  - 함대는 좌우 3분의 1에 있고, 교전선은 타이머 위아래 띠입니다(프롬프트 13.3절).
  - 함선은 3/4 시점의 스프라이트이며, 화면에 동시에 24척까지 그립니다.
- **성계 무대**
  - 붉은 별 텍스처, 비스듬한 타원 궤도 7개, 행성 원반(생태 색 + 종족 테두리 + 단계 장식), 항로 점선(Graphics, 바뀔 때만 다시 그림)으로 이뤄집니다.
  - 타이머 사각형 안에 들어온 행성은 투명도 0.25입니다.

### 6.5 무대 전환 (StageDirector)

- 입력은 `Battle.planet !== 전선 행성`이고 `!cameraLock && motion`일 때입니다.
- 진행: 시작 10초 전 줌아웃 5초(지상 → 성계) → 줌인 5초(성계 → 대상 행성의 무대) → 전투 → 20~40초 머묾 → 돌아오기 10초
- 전환 중에는 Director에 `quiet`을 넘깁니다. 장면 자체 카메라라 호스트의 `cameraMoving`이 반영되지 않기 때문에 장면이 직접 막습니다.
- `jumped`이면 늘 기본 무대로 돌아갑니다. 동작 줄이기에서는 1초 페이드입니다.
- 다른 행성의 지형은 전환이 시작될 때 칠하기 시작합니다. 프레임마다 시간 예산(4ms)만큼 나눠 칠하고, 덜 칠했으면 저해상도판을 먼저 씁니다. 캐시는 두 행성까지입니다.

### 6.6 그림과 텍스처

- 텍스처는 은하처럼 고정 페인트 시드로 한 번 칠합니다. 세계 시드는 배치에만 씁니다.
- **종족 아틀라스**: 건물 11종, 지상 유닛 9종, 함선 3종, 기함 1종. 건물은 건설 단계 4장(기초·골조·외벽·완성)으로, 유닛은 자세 2장(서기·걷기/쏘기)으로 칠합니다.
  - 연합: 우주의 `paintColony` / `paintArmy` 붓 함수를 참고해 새 실루엣(4.1절)으로 다시 칠합니다. 우주 장면 폴더는 지우므로, 필요한 붓 조각은 `scene/front/paint/`로 옮겨 씁니다.
- **지형**: `fbmField`(은하 `noise.ts`)와 같은 방식의 노이즈를 `scene/front/noise.ts`에 따로 둡니다. 행성마다 높이·색 필드를 만들고, 고지대 절벽 띠와 경사로를 칠해 굽습니다. 행성·종횡비마다 1장이고, 저전력이면 해상도를 절반으로 합니다.
- **안개·영토 마스크**: `Uint8Array(160×90)`를 사건 때 갱신하고, 텍스처를 업로드한 뒤 흐림을 넣어 확대해 씁니다.
- 빌드 시간 목표는 첫 행성 텍스처 전체 600ms 이하(개발 기기)입니다. 칠하는 사이사이 이벤트 루프에 양보합니다(우주 `textures.ts`의 `tick`).

## 10. 위험

- **범위가 매우 큽니다.** 세 종족의 건물 11종 × 유닛 9종 × 함선 4종 그림, 무대 셋, 무대 전환이 있습니다. 그래서 Phase마다 한 종족 또는 한 무대만 늘리고, 검수를 통과해야 넘어갑니다.

- 닫힌 형태라서 "적이 실제로 반응하는" 깊은 상호작용은 없습니다. 모든 전투는 일정과 계획의 재생입니다. 대신 결정성과 분할 독립이 보장됩니다.

- 실기기 성능은 측정할 수 없습니다. CPU 감속은 대용 측정으로만 보고합니다.
- 독자 디자인은 프롬프트 16절 점검표로 지킵니다. 법적 검토는 아닙니다.
